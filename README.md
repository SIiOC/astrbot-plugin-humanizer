# astrbot_plugin_wanna_be_human — 好想成为人类啊

> 本插件原名 `astrbot_plugin_humanizer`，自 v3.3.0 起更名为 `astrbot_plugin_wanna_be_human`（display_name 与功能不变，GitHub 仓库不变）。从旧名升级的迁移步骤见文末与安装说明。

自动去除 AI 回复中的写作痕迹，让对话更自然、更有真人感。**插件启用后无需任何手动指令，每条 AI 回复都会自动经过人性化处理。**

<p align="center">✨ 如果这个插件让你的 Bot 更有点"人味"，欢迎点个 <a href="https://github.com/SIiOC/astrbot-plugin-humanizer/stargazers">Star ⭐</a> 支持持续更新 ✨</p>

整合自两个技能：

- **[Humanizer-zh](https://github.com/op7418/Humanizer-zh)**：中文 24 种 AI 写作模式（基于维基百科 [Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)）
- **[stop-slop](https://github.com/hardikpandya/stop-slop)**：英文去 AI 痕迹核心规则与参考表

## 安装

### 方式一：WebUI 安装 zip（推荐）

在 AstrBot WebUI 的「插件管理」→ 安装插件中，选择本插件打包的 `astrbot_plugin_wanna_be_human.zip` 上传安装，或直接拖入。

### 方式二：手动放置

将 `astrbot_plugin_wanna_be_human` 文件夹（或解压 zip）放入 AstrBot 的 `data/plugins/` 目录：

```

            ├── main.py                  # 装配层：钩子、命令、接线
            ├── web_api.py               # 控制台后端路由（20 个端点）
            ├── _conf_schema.json        # 配置面板单一事实源（7 组 157 键）
            ├── requirements.txt         # 软依赖 lunar_python（历法感知）
            ├── README.md / CHANGELOG.md / LICENSE / 安装说明.txt
            ├── corpora/base.jsonl       # 内置语料池（公开语料采样，约 10379 对）
            ├── humanizer_core/          # 纯函数 core（零 astrbot 依赖）
            │   ├── rules_zh.py / rules_en.py    # 真人感规则（中/英）

            │   ├── parrot.py / dedupe.py / lang_mirror.py / llm_*.py
            │   └── config_migrate.py / config_facade.py / state*.py / task_registry.py
            ├── services/                # 可注入服务（KB / 主动状态 / 语言画像）
```

> 要求 AstrBot >= 4.5.7（依赖 `on_llm_response` hook 与插件配置注入机制）。

## 使用

启用即生效，无需任何命令。处理流程：

1. 每条 AI 回复生成后，`on_llm_response` hook 自动接管
2. 自动检测语言（中文/英文）：
   - 中文：清除 AI 客套话（"希望这对您有帮助"等）、知识截止免责声明、填充语（"值得注意的是""此外"等）、"——"破折号滥用、过度限定、表情符号、通用积极结尾、否定式排比开头等
   - 英文：清除 throat-clearing openers、emphasis crutches、filler phrases、空泛副词、em-dash、商业行话、meta-commentary 等
3. 开启配置 `enable_llm_rewrite` 后，先调用大模型按合并后的技能指南深度改写，失败自动回落规则清理。默认跟随当前会话的模型；可在 `rewrite_model` 中指定用于深度改写的模型，或直接用命令选择（见下）。

## 深度改写模型选择

配置弹窗里的「深度改写模型」提供 **"选择提供商" 按钮**——点击弹出对话框，列出你所有已配置的提供商与模型，选中即保存（值为 `提供商/模型`，如 `xiaomi-token-plan/mimo-v2.5-pro`），无需手填。留空（不选择）则跟随当前会话模型。也可用命令查看/选择：

- `/humanizer_models`：列出所有已配置提供商及其可用模型（带编号）
- `/humanizer_model <编号>`：从列表中选择一个模型
- `/humanizer_model <模型名>`：直接指定模型名（会校验存在于已配置提供商）
- `/humanizer_model off`：恢复跟随当前会话模型
- `/humanizer_model`：查看当前设置

命令为管理员权限，效果等价于修改 `rewrite_model` 配置项并自动保存。

### 模型故障切换（v2.6）

开启深度改写后，改写请求会自动尝试**候选模型序列**（首选 `rewrite_model` 或当前会话模型，其余已配置提供商按序补全、去重）。某个模型**传输失败**（连接失败/HTTP 错误，即调用抛异常）时立即切换到下一个候选，不再反复消耗同模型重试；**内容校验失败**（空输出/改写结果膨胀 >2 倍）才回落规则清理——问题在内容，切模型无意义。全部候选都传输失败时回落规则清理。切换模型成功会记一条日志，无需手动配置。

## 主动聊天（默认关闭）

用户沉默一段时间后，插件主动调用大模型生成一句自然的话发到该会话，实现"主动找用户聊天"。

- **开关**：`enable_proactive`（默认 `false`）。开启后，插件会在聊过的会话中检测沉默时长。**默认仅跟踪私聊**；`proactive_track_groups` 开启后才跟踪群聊。
- **重启不丢状态**：聊过会话的跟踪状态持久化在插件数据目录，重启 AstrBot 后无需重新发消息激活（超 24 小时无活动的会话自动清理）。
- **触发时机**：`silence_after_minutes`（默认 45 分钟）——用户最后一条消息后多久触发；`silence_fluctuation_minutes`（默认 15）控制随机波动幅度（45±15 = 30~60 分钟，填 0 固定不波动，均受 30 分钟下限约束）。触发后按同样规则随机重排下次。
- **勿扰时段**：`proactive_quiet_hours`（默认 `01:00-07:00` 凌晨勿扰；如 `22:00-07:00` 支持跨天），此时间段内不主动发。
- **提示词**：`proactive_prompt`（留空用内置模板），支持 `{persona}`、`{last_user}`、`{last_ai}` 占位符。`{persona}` 自动替换为**该会话在 AstrBot 中配置的人设**（未配置则用兜底句），主动消息会以你的人设口吻发起。
- **内容**：主动消息走**完整 Agent Pipeline**（CronMessageEvent + build_main_agent）——**其他插件的上下文注入（风格、记忆等）对主动消息生效**，问候会带上你配置的风格与记忆；发送走完整装饰/响应阶段（分段、TTS、记忆巩固等）。旧框架不支持时自动回落到轻量路径（直接生成 + 去 AI 痕迹 + 发送）。

- **插话丢弃与输入让位（v3.2）**：主动消息生成耗时数十秒，期间用户发言则本次自动放弃（不写历史、不计未回复）；对方"正在输入"时同样让位（需要 NapCat 等支持 input_status 的平台，微信无此信号自动跳过）。命中次数计入统计 `proactive_interject_dropped`。
- **会话白名单（v3.2）**：`proactive_session_allowlist` 留空 = 所有聊过的会话生效；填写会话 UMO（如 `qq_napcat:FriendMessage:123456`，可在日志「主动消息 prompt(...)」行或控制台主动聊天页查看）后仅这些会话触发，白名单外的会话（含更换平台前的残留）自动清理。多个 UMO 用换行或逗号分隔。

⚠️ **副作用**：每次主动消息都会调用一次大模型（消耗 token）；可能打扰用户；建议配合勿扰时段使用。仅在"聊过"的会话触发，不会对陌生人发消息。

## 消息防抖（v3.2 并入，默认开启）

合并短时间内的连续私聊消息后统一回复，避免多条短消息连续发送（能力自独立插件 astrbot_plugin_chat_debounce 并入，仅私聊生效）。

- **能力**：固定/自适应防抖（按消息长度、结尾标点、连续短句动态等待）、指令中断、空内容吸收、撤回过滤、输入状态暂停/恢复、会话硬死线兜底（`max_session_wait` 60 秒强制结算）。
- **配置**：`debounce` 分组（防抖时间/自适应参数/指令前缀/合并分隔符等），保存后即时生效，无需重载插件。
- ⚠️ **请停用并移除原独立插件 astrbot_plugin_chat_debounce**：两层防抖会对私聊消息叠加延迟、行为错乱。

## 动态一天状态（v2.5，默认开启）

让 AI 拥有随真实时间推进的一天生活——每次 LLM 请求自动注入「【你的当前状态】」（当前日期/星期/自然时段/时间 + 正在做什么 + 当日心情），让回复带生活感、能感知"此刻自己正处在一天中的哪个位置"。

- **零成本**：纯本地计算（日程模板按真实时间映射 + 按日期确定性选心情），不消耗任何模型调用、零延迟。
- **一天日程模板**：多行 `HH:MM 描述` 按真实时间映射「现在在做什么」（默认内置一套作息）；模板未覆盖的时段（如凌晨）用「兜底状态」。
- **当日心情**：从心情池按日期确定性选一个——同一天内稳定、跨天自然变化。
- **注入方式**：走 AstrBot 标准 `extra_user_content_parts` 路径，不污染 system_prompt，与风格注入/记忆插件同源共存；**独立于风格开关**（关闭风格注入时生活状态仍生效）。
- **主动消息**：主动聊天模板支持 `{life}` 占位符引用生活状态块（仅显式引用时替换，避免与 Agent Pipeline 注入重复）。

### LLM 每日生活时间线（v3.0 起，默认关闭）

基础模式是「模板映射」——固定作息、按时间点切换；若想要更强的「一天有在过日子」的感觉，可开启 **`enable_llm_timeline`**：

- **每天 00:05 自动生成当天生活时间线**：用大模型规划当天一天（5+ 个时段：`08:00-12:00 居家休息`、`下午 咖啡店打工 | 心情:带劲 | 地点:咖啡店`…），生成时参考**近 7 天历史**保持连贯（昨天加班今天休息、前天去过的店今天换一家）。
- **对话时按真实时间选中当前时段**注入：`下午（14:00-18:00） · 咖啡店打工 · 心情带劲 · 在咖啡店（今日：打工的一天）`。
- **自动回退**：生成失败超过 3 次自动回退到基础日程模板；生成期间不阻塞回复（本次只跳过时段行，时间/间隙照常注入）。
- **可配置**：`extract_model` 指定生成模型（默认跟随会话模型）、`prompt_template` 自定义生成提示词（支持 `{date}`/`{persona}`/`{history}`/`{extra}` 占位符，必须包含 `{date}`）。
- ⚠️ **副作用**：每天消耗一次 LLM 调用（外加对话首次请求时可能触发一次补生成），建议指定专用模型。

## 时间流动感知（v3.0，默认开启）

让 Bot 感知对话间的时间流动——每次 LLM 请求注入 `<time_context>` 块：**当前时间**（日期/星期/时分）+ **距上次交流的时长**（如「隔了大半天」）。LLM 没有时钟也没有状态，这块信息让回复能自然带出"哦你这两天没找我"式的时间感。

- **间隙感知**：每条消息（含 Bot 发言）都会刷新会话活动时间并落盘 `time_state.json`（重启不丢）；下次对话时按"距双方最后一条消息"计算间隔。
- **三档粒度**：`mixed`（默认）30 分钟内视为连续对话不注入；30 分钟~24 小时精确到分钟（"2小时30分钟"）；超过 24 小时切粗粒度（"隔了大半天"），绝不出现"65 小时 12 分钟前"式机器精度。`coarse` 始终粗粒度；`precise` 始终精确。
- **合并注入**：时间 + 间隙 + 生活状态统一在一个 `<time_context>` 块里，墙钟只出现一次，不与其他插件重复。
- **群聊**：默认仅私聊生效，跟随「主动聊天」的 `proactive_track_groups` 开关。

## 对话节奏引擎（v3.5.0，默认开启）

让回复节奏跟随对话热度自动变化：连续对话时回复更快更简短，间隔较久后放缓节奏、降低语气热度。

- **热度三档**：按距用户最后发言的间隔自动分档——热聊（hot，间隔 < 沉默触发时长×1/5）/ 常态（warm）/ 冷场（cold，间隔 ≥ 沉默触发时长×2/3）。分档界线从「主动聊天」的沉默触发时长派生，调整主动消息间隔时分档自动缩放。
- **延迟融合**：热聊时打字延迟覆盖为快回窗口（默认 1.5~4 秒，快回意图优先、忽略打字组「延迟下限」，仍受「延迟上限」约束）；冷场在正常延迟上叠加「隔了一会儿才看到消息」的随机延迟（默认 +10~25 秒）；常态保持自然基线。
- **节奏指令**：热聊提示回复轻快简短、冷场提示轻描淡写一句带过；常态不注入、不占 token。
- **可配置**：7 个键都在「时间流动」分组（见下方配置项③）——总开关、两个分界比例、快回窗口与冷场附加延迟窗口；窗口下限>上限自动互换。
- **与主动消息闭环**：主动消息触发点天然落在冷场段末尾——冷场后的对话按「重新开场」处理，与主动消息的重新连接语义一致。

## 检索重排（v3.5.0，默认不干预）

「人类对话风格」的检索示例注入支持 rerank 精排：先召回更大的候选池，再由重排模型按相关性挑选最像当前话题的示例注入。

| 配置（人类对话风格分组） | 默认值 | 说明 |
|------|--------|------|
| `rerank_provider_id` | 空 | 检索精排用的 rerank 模型，下拉列出 AstrBot「模型供应商」中已配置的 rerank 类型提供商。**留空 = 不干预**，跟随知识库自身的重排配置（框架「知识库」页可按库配置）；选定后插件把本插件的检索库同步为该提供商 |
| `rerank_candidates` | `12` | 有重排时先召回的候选片段数（≥ 检索示例条数，上限 30），精排后取「检索示例条数」条注入 |

> 重排供应商不可用时自动跳过重排，不影响回复；清除重排请到框架「知识库」设置。

## 情绪惯性（v3.5.1，默认开启）

跨消息维持轻微情绪状态：未获回应时语气转淡，获得积极回应时转向愉悦，强度随对话逐条衰减。语气具有连续性，而非每条回复从零开始。

- **三档情绪**：平静（neutral，默认）/ 有点小情绪（sulky）/ 心情不错（appy）。强度 0~1，低于阈值自动回到平静。
- **生气档可选**：打开「主动聊天 → 未回复小情绪」（默认关）后，主动消息连续未获回复时，后续对话回复会带轻微的低落语气（克制表达，不含指责）；该开关同时控制主动消息文案与对话侧情绪。
- **安抚恢复（v4.1.0 降格为加分项）**：用户消息命中安抚/积极词池（哈哈/谢谢/抱抱/喜欢你等，可自定义）时情绪转向「心情不错」——但量级从一锤定音的固定 0.4 降为约**一条热聊消息**（可配 `emotion_soothe_boost`，默认 0.2，**设 0 完全关闭安抚词效果**）：情绪基调由对话热度主导，关键词只是锦上添花；仍最后执行，冷场中的一句好话依然能转向愉悦。用户每发一条消息情绪强度 ×0.6 逐条衰减。
- **情绪×对话热度耦合（v4.1.0，默认开）**：对话热度直接参与情绪推进——热聊（连续快节奏往来）每条消息向「心情不错」漂移，话题冷掉（间隔拉长）向「有点小情绪/平淡」漂移，**热度是情绪的主导来源**。灵敏度：热聊**首条回复即带轻快劲**（+0.2 已越过注入阈值），冷场两条起见效（负面情绪建得比正面慢）；稳定强度约 0.50（热聊）/ 0.25（冷场）；首条消息不因"冷档"摆脸色（初见≠冷场）。三键可调：`emotion_heat_drift_enable`（总开关）/ `emotion_hot_drift` / `emotion_cold_drift`（漂移量，设 0 关闭该方向）。与冷落降温弧线互补：弧线管按天的沉默，这里管分钟级的聊天节奏。
- **注入与防洗**：情绪指令行注入 system_prompt（平静时不注入、不占 token）；深度改写链同步携带当前节奏与情绪状态，防止改写把语气洗回书面体。
- **持久化**：persona_state.json 按会话保存，重启不丢；损坏自动回落平静。

## 真人感规则（v3.5.2，注入默认开）

自定义对话规则库（存于插件数据目录 `humaneness_rules.json`，内置五条预置：时间感知检查、语气词限额、禁宣誓句、长度镜像、禁表演感描写），两级执行：

- **注入型**（默认开）：启用的规则随系统提示词发给模型，生成前约束表达，独立于风格开关。
- **质检型**（默认关，独立开关）：生成后按质检关键词（逗号分隔多个；以 `re:` 开头按正则）检查回复，命中触发一次针对性改写；改写后仍命中则放行原文——不循环、不吞消息。
- **命令管理**（管理员，即时生效无需重启）：`/rules_list` 列表、`/rules_add <名字> <inject|qc> <内容>` 新增、`/rules_del <序号|名字>` 删除（内置规则不可删、只能停用）、`/rules_on|off <序号|名字>` 开关、`/rules_reload` 手改文件后重载。
- 内置预置规则首次启动自动写入，删掉规则文件重启即恢复预置；用户自定义规则随插件数据目录保存，插件更新不丢失。

## 分段发送与连续性感知（v3.6.0）

- **分段发送**（打字延迟组 `split_enable`，默认关）：超过阈值（默认 40 字）的长回复按句读拆分为 2~3 条消息依次发送，段间隔可配置（默认 0.5~3 秒随机，另有可调概率的长间隔模拟输入耗时）；发出前检测到新入站消息即中止剩余段。仅做切分、不改写内容，各段拼回与原文一致；待发链含图片/语音等非文本组件时不拆分。可调 `split_threshold` / `split_max_segments` / `split_min_part` 与段间隔五项参数。
- **对话连续性分级**（时间流动组 `continuity_inject`，默认开）：把「距上次交流多久」翻译成五档开口方式——短中断（接上话头别重新打招呼）/ 同日回归 / 隔夜（衔接昨天的事）/ 隔几天（自然问近况）/ 久别重逢（不追问为何没来）。间隔 ≥30 分钟起注入，与节奏引擎互补（节奏管半小时内的回复快慢，连续性管半小时以上的开口分寸）。主动消息同样注入——bot 主动开口时也知道多久没联系对方。
- **真人感规则补库**：内置预置从 5 条扩到 10 条（禁强行提问收尾、禁客服腔、禁过度附和等），存量用户启动时自动幂等补齐。

## 时间流逝增强（v3.7.0）

让 Bot 感知「距上次交流多久 / 现在几点 / 相识多久 / 今天什么日子」，并据此调整开口方式与语气。承接 v3.6.0 的连续性分级，本版补齐时间轴与历法维度：

- **时间上下文不入历史**（修复）：每轮 `<time_context>`（墙钟 + 距上次交流 + 生活状态 + 节奏 + 连续性 + 历法 + 相识天数）临时注入当前轮，随消息历史持久化时自动剥离（`mark_as_temp`）——不再累积过期时间块、不浪费 token。
- **情绪随时间淡去**：新增时间衰减（半衰期默认 8 小时，可配 `emotion_time_half_life_hours`，0=关闭），隔几天回来不把分离前的小情绪原样带进回复；久别重逢时情绪指令换成「淡了但温度还在」的重逢版（不翻旧账、不过度热情）。
- **历法感知**（需 `lunar_python`，缺库自动静默关闭）：注入当日农历、传统节日与节气；敏感日（清明/中元/寒衣/国家公祭日等，可自定义追加）自动替换为「安静贴心、别庆祝别开玩笑」的说话护栏。⚠️ 若另装时笺（time_awareness）等历法插件会重复注入，二选一。
- **相识天数**：可选注入「这是你们认识的第 N 天」（`include_first_seen`，默认关），首见时间按北京时间自然日进位。
- 会话活动/首见时间持久化 time_state.json（v2，向后兼容旧数据），重启不丢。

## 双向间隔 · 冷落弧线 · 承诺簿（v3.8.0）

时间感知收尾与主动性深化，全部旁路注入、默认关或零开销，不改变既有行为：

- **双向间隔感知**（`include_last_chat`，默认关）：用户与 Bot 各自独立计时，注入「对方最后发言 X · 你最后发言 Y」。补合并口径的盲区——你发的主动消息没人回时，「距上次交流」按 Bot 自己算显得没隔多久，这行让模型看到对方实际沉默了多久。超一周回落到具体日期；正在即时对话（双侧均 <1 分钟）不注入。time_state.json 升 v3（向后兼容 v2/v1）。
- **冷落降温弧线**（`emotion_cold_war`，默认关）：对方持续不回复时，主动消息语气随沉默时长递进——想念(1 天)→试探(3 天)→失望(7 天)→抽离(14 天，各档阈值可配)。弧线以对方沉默为尺（Bot 自己的发言不打断它），开启后顶替按条数累计的「未回复小情绪」；只收着不归零，抽离档也留一次极轻触点。配套的情绪恢复曲线分档：缺席 ≥2 天后小情绪改按 48 小时半衰期慢衰，久别的余温留得更自然。
- **主动消息迟到补发**（`proactive_late_threshold_minutes`，默认 15）：宕机跨点/免打扰压单导致主动消息比预定时刻晚发超阈值时，开口自然带一句「来晚了/让你等了」，不反复道歉；按时送达则完全不提。
- **承诺簿**（`commitments.enable`，默认关）：记住自己答应过的事——从回复里捕捉带明确时间锚点的承诺（如「明天帮你查那个报错」），到期日起 2 天内注入「你答应过对方的事到期了：…」提醒它主动汇报兑现或轻量说明；超 7 天自动作废不追账。管理员命令：`/commitment_list` 查看、`/commitment_done <序号>` 核销、`/commitment_drop <序号>` 作废。可选后台 LLM 复核捕捉（默认开，超时静默回落正则，不阻塞对话）。
- **时间行为规则入库**：真人感内置预置 10→14 条（时间只依据注入/时间口语化/间隔调语气/历法自然贴合），首次启动自动幂等补齐。

## 主动消息 v2 · 话题与追问 · tells 补库（v3.9.0）

## 应声虫复读（随 v4.0.0 一并上线；原文标注「v4.1.0 未发布」系版本号排期变更的遗留）

**用户发搞怪消息时，小概率原样学舌。** 当用户发出不正经/搞怪的消息（连续笑声「哈哈哈哈」、纯标点玩梗「？？？」、颜文字、玩梗口头禅「笑死」「绷不住」）时，机器人以**默认 8% 概率原样复读**该条消息——还原网络上「应声虫」跟着复读的玩梗行为，让陪伴多一分玩闹感。

- **只在私聊、只对搞怪消息抽签**：因此实际复读频率远低于 8%，不会变成"鹦鹉"。
- **保守判定**：含真实疑问（吗/怎么/几点）或正经诉求（帮我/请问/求）的消息一律不学舌；只在 1~24 字的短促消息上考虑。单字梗（草/典/6）须独立成句——"草莓""典礼"不会误伤。
- **防连发**：复读一次后默认 8 轮内不再抽签；每会话每天上限 4 次，跨日自动重置。
- **纯原样**：命中后整条回复就是用户那句话，不加字、不改标点。
- **两种判定方式**：默认「关键词」（零成本零延迟）；可切「LLM 语义判定」——让模型判断搞怪程度（0~10 分，默认 ≥7 才复读），能捕捉反话、冷幽默、阴阳怪气等关键词抓不到的语气。语义档每条约 3% 的消息会调用一次模型（命中抽签才算），可指定便宜的判定模型。
- 默认**关闭**；在配置面板「复读 · 应声虫学舌」分组开启即可。可调概率、冷却、每日上限、长短限制、判定方式与自定义玩梗词表。

| `enable_llm_rewrite` | `false` | 是否调用大模型深度改写（更自然，但每条消息额外消耗 token） |
| `rewrite_model` | 空 | 深度改写使用的模型名。留空跟随当前会话模型；填写模型名（如 `gpt-4o`、`deepseek-chat`）时，优先在当前会话的提供商内切换，不支持则自动在其它已配置提供商中查找，都找不到回落当前会话模型。**插件运行后配置弹窗会显示为你已配置模型的下拉列表**，也可用 `/humanizer_model` 命令选择 |
| `remove_emoji` | `true` | 移除表情符号 |
| `remove_reasoning` | `false` | 移除思考过程：隐藏模型生成的"🤔 思考: ..."，回复只显示正式内容（默认关闭，仅隐藏不阻止思考，见下方副作用说明） |
| `min_length` | `8` | 短于此长度的回复不处理 |
| `max_chars` | `300` | 长于此长度的回复只做规则清理，不 LLM 改写 |
| `debug` | `false` | 规则命中时输出命中阶段日志，便于排查误伤 |

**② 主动聊天**（proactive）——用户沉默后主动发消息：

| 配置 | 默认值 | 说明 |
|------|--------|------|
| `enable_proactive` | `false` | 主动聊天总开关（用户沉默后主动发消息） |
| `proactive_track_groups` | `false` | 是否跟踪群聊（默认仅私聊；群内任何成员发言都会刷新计时器，慎用） |
| `silence_after_minutes` | `45` | 静默多少分钟后触发主动聊天（下限 30，触发后重排） |
| `silence_fluctuation_minutes` | `15` | 静默时长随机波动幅度（±分钟，0=固定不波动） |
| `proactive_quiet_hours` | `01:00-07:00` | 主动聊天勿扰时段（`HH:MM-HH:MM`，支持跨天，空=不限） |
| `proactive_prompt` | 空 | 主动聊天消息的提示词模板（支持 `{persona}`/`{last_user}`/`{last_ai}`），留空用内置 |

> 旧版扁平配置会自动迁移到分组结构，用户设置不丢失；v2.0.0 起主动聊天键名改为 `silence_*`（旧键名自动迁移）。

**③ 时间流动**（time，v3.0）——让 Bot 感知对话间的时间流动：

| 配置 | 默认值 | 说明 |
|------|--------|------|
| `enable_gap` | `true` | 时间上下文注入总开关（关闭后时间/间隙/生活状态都不注入） |
| `gap_granularity` | `mixed` | 间隙文案粒度：`mixed`=30 分钟内不注入、30 分钟~24 小时精确到分钟、超 24 小时切粗粒度；`coarse`=始终粗粒度分档；`precise`=始终精确 |
| `gap_threshold_minutes` | `30` | 距上次交流不足该分钟数时不注入间隙行（视为连续对话） |
| `include_wall_clock` | `true` | 是否注入当前时间（日期/星期/时分） |
| `rhythm_enable` | `true` | 对话节奏引擎总开关（热度分档 + 延迟融合 + 节奏指令） |
| `rhythm_hot_ratio` | `0.2` | 间隔 < 沉默触发时长×此比例 视为热聊（默认 1/5） |
| `rhythm_cold_ratio` | `0.667` | 间隔 ≥ 沉默触发时长×此比例 视为冷场（默认 2/3），需大于热聊比例 |
| `rhythm_delay_hot_min` / `rhythm_delay_hot_max` | `1.5` / `4.0` | 热聊快回窗口（秒）：延迟直接落在此区间内（另加快打耗时），忽略延迟下限、尊重延迟上限 |
| `rhythm_delay_cold_min` / `rhythm_delay_cold_max` | `10.0` / `25.0` | 冷场附加延迟窗口（秒）：在正常延迟上叠加，模拟"隔了会儿才看到" |
| `debug` | `false` | 时间上下文注入日志 |

**④ 动态一天状态**（life，v2.5）——让 AI 拥有随真实时间推进的一天生活：

| 配置 | 默认值 | 说明 |

| `enable_life` | `true` | 生活状态注入总开关 |
| `enable_llm_timeline` | `false` | 启用 LLM 每日生活时间线（每天 00:05 自动生成当天安排，跨天连贯；生成失败自动回退日程模板）。⚠️ 每天消耗一次 LLM 调用 |
| `extract_model` | 空 | 时间线生成模型（留空跟随当前会话模型） |
| `prompt_template` | 空 | 时间线生成提示词模板（支持 `{date}`/`{persona}`/`{history}`/`{extra}`，必须含 `{date}`） |
| `schedule` | 内置作息模板 | 一天日程模板：基础模式用 `HH:MM 描述`；LLM 时间线模式作回退，支持 `HH:MM-HH:MM 安排 \| 心情:… \| 地点:…` 富语法 |

## 设计说明

- **规则保守**：只处理高置信度的机械痕迹（套话、填充语、标点、高频词），不重写语义、不删减实质内容，避免误伤正常对话。
- **保留结构**：空白折叠只作用于空格/制表符，**换行符不受影响**——多段落回复、Markdown 表格、代码块结构完整保留；仅将 3 个及以上连续空行收敛为 2 个。
- **破折号区分处理**：中文破折号仅在出现 ≥2 次且两侧都是实际文字（插入式用法）时收敛为逗号，声音延长（"啊——"）等合法用法保留；英文仅处理 em-dash（—），en-dash（–）数字区间（如 2020–2026）保留。
- **递归保护**：LLM 改写请求不会再次触发本插件的 hook，防止死循环。
- **指定改写模型**：`rewrite_model` 支持跨提供商查找目标模型（模型列表结果缓存，避免每条消息重复向模型商查询）。
- **版本兼容**：自动检测 `llm_generate` 是否支持 `system_prompt` 参数，兼容不同 AstrBot 版本签名。

## ⚠️ 副作用与注意事项

使用前请了解以下行为，避免预期偏差：

- **移除思考 ≠ 阻止思考**：`remove_reasoning` 默认关闭；开启后只是让思考内容不显示在回复里，**模型仍会照常思考，思考产生的 token 照常计费**（推理模型如 mimo-v2.5-pro、deepseek-reasoner 的思考 token 通常更贵）。想真正省 token，请在模型提供商配置中关闭 thinking（如 `anth_thinking_config`），或改用非推理模型。
- **思考被无差别移除**：`remove_reasoning` 开启后，**所有**回复的思考内容都会被清除，包括你可能想查看的推理过程。如需查看某个模型的思考，请关闭此开关。
- **深度改写消耗额外 token**：开启 `enable_llm_rewrite` 后，每条消息会额外调用一次大模型，token 消耗和延迟都会增加；`max_chars` 只限制长文本跳过改写，不限制改写本身的成本。
- **规则清理可能误伤**：去 AI 痕迹的规则采用保守设计，但在个别情况下仍可能误删内容（如免责声明、破折号、英文副词）。如发现误伤，可关闭 `debug` 查看命中日志、关闭相关规则或整体关闭插件。
- **语言检测**：中英混排文本可能误判走另一语言规则集，但规则副作用已最小化（不破坏换行、代码块、数字区间等结构）。
